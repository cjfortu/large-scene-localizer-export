# Large-Scene Localizer

> **This package ships no trained weights.** `checkpoints/` holds only the
> three `<name>.json` manifests that describe the weights every number below
> was measured with. Day one is: restore the file names, install, run the
> tests, generate the data, retrain the three models, and compare against the
> manifests' `val_metrics` (the targets, with the tolerances of
> `docs/results.md`, section 7). See "No weights in this package: day one"
> below. If the weight files arrive separately, see "If the weights arrive
> separately".

A staged, learned pipeline that finds small moving targets (one to a few
pixels across) in large overhead video volumes of shape frames x height x
width (64 x 512 x 512 measured; 64 x 1024 x 1024 is the design target).
Stage 1, a CNN + Mamba **gate**, scans the whole scene and flags which
128 x 128 px regions may contain movers. Stage 2, a 3D CNN + attention
**classifier**, decides mover / no mover for each flagged 128 x 128 x 64
chip. Stage 3, a volumetric U-Net + 3D Swin **segmenter**, produces a
per-voxel mover mask for a chip. All training and evaluation data are
synthetic (generated by `localizer.synth`).

## Status

**Gate -> classifier is measured end to end on 512² synthetic data. The
segmenter is validated standalone only; its shipped weights are the epoch-19
checkpoint (val Dice 0.391), and integrating it after the classifier is open
work.**

## Hardware and OS support

| Tier | OS | Hardware | What it supports |
|---|---|---|---|
| **0 (CPU)** | Any: Windows (including JupyterLab), Linux, macOS | CPU | Install, tests, loading all three checkpoints, inference, notebooks, the pipeline evaluation on small inputs. The gate's Mamba blocks run a pure-PyTorch reference: same weights, same decisions, slower. |
| **0 on GPU** | Windows, or Linux without a compiler | NVIDIA GPU, driver supporting CUDA 13.0 | Tier 0 with the CUDA build of torch, nothing to compile. Full-size inference and evaluation fit a 24 GB card (300-scene gate rescore 81 s vs 43 s with the kernels). Gate training at 512² with the reference Mamba needs 33.4 GiB (a GPU with more than 40 GB; out of memory on 24 GB) and is about 3.4x slower per batch (same-hardware measurement, epoch extrapolated). |
| **1 from source** | Linux x86-64 (Windows: WSL2) | NVIDIA GPU, driver supporting CUDA 13.0; CUDA 13.0 toolkit to build | Everything, with the fused Mamba kernels compiled locally from the pinned PyPI sources (about 12 minutes of compiling on 8 CPU threads; `docs/environment.md`) or in the `Dockerfile`. |

**The fused Mamba kernels do not build on Windows** (they are Linux-only
upstream). Windows users run Tier 0 natively, on CPU or GPU, or Tier 1
inside WSL2. The weights ship as `.safetensors`; nothing in this repository
is a binary wheel or a pickle.

GPU memory: everything at 512² with the shipped gate fits a 24 GB card
(gate training peaks at 8.05 GiB allocated). 1024² does not: the shipped gate
architecture needs 31.8 GiB allocated to train one 1024² scene, and the
stride-1 stem variant needs about 112 GiB, which is why all 1024² work was
done on 128 GB unified-memory GPUs. Details in `docs/environment.md`.

## Restoring the transferred tree (do this first)

The transferred snapshot (the release zip, or a clone of the transfer
repository) carries no executable file extensions: every script and
executable-type file (`*.py`, `*.sh`, `*.ps1`, `Dockerfile`, `.dockerignore`)
has `.txt` appended, and `TRANSFER_RENAMES.txt` lists each pair. Restore
the original names before any other command. The restore script first
checks every file against `MANIFEST.transfer.sha256`, then renames the
files back (it never overwrites an existing file), then checks the restored
tree against `MANIFEST.sha256`, and ends with one `PASS` or `FAIL` line. If
the file names here already end in `.py`, there is nothing to restore.

Linux (POSIX `sh`; needs only `mv`, `sha256sum`, `awk`):

```bash
sha256sum -c large-scene-localizer-export-v5-2026-11-13.zip.sha256
unzip -q large-scene-localizer-export-v5-2026-11-13.zip                 # or: python3 -m zipfile -e large-scene-localizer-export-v5-2026-11-13.zip .
cd large-scene-localizer-export-v5-2026-11-13                           # or the directory of a clone of the transfer repository
cp restore_names.sh.txt restore_names.sh
sh restore_names.sh                                              # expect: PASS: ...
```

Windows (PowerShell 5.1 or later):

```powershell
(Get-FileHash large-scene-localizer-export-v5-2026-11-13.zip -Algorithm SHA256).Hash -eq (Get-Content large-scene-localizer-export-v5-2026-11-13.zip.sha256).Split(' ')[0]   # expect: True
Expand-Archive large-scene-localizer-export-v5-2026-11-13.zip -DestinationPath .
cd large-scene-localizer-export-v5-2026-11-13                           # or the directory of a clone of the transfer repository
Copy-Item restore_names.ps1.txt restore_names.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File .\restore_names.ps1   # expect: PASS: ...
```

- `cmd` users can print the zip's hash with
  `certutil -hashfile large-scene-localizer-export-v5-2026-11-13.zip SHA256`
  and compare it with the `.sha256` file.
- The zip has no `.git` directory. `PROVENANCE.md` records two git tree
  hashes (the tree as transferred and as restored) and the four `git`
  commands that check them on any OS.
- In a clone, `.gitattributes` (`* -text`) stops git from converting line
  endings, so the hashes hold. After the restore, `git status` lists the
  renames; that is expected.
- No file carries an executable mode bit. Every command in these docs calls
  `python`, `bash` or `docker` explicitly, so none needs one.

## Quickstart (Tier 0, about ten lines)

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
python -m pip install -r requirements/base.txt
python -m pip install -e . --no-deps
export LSL_DATA_ROOT=$PWD/work/data LSL_RUNS_ROOT=$PWD/work/runs LSL_CKPT_ROOT=$PWD/checkpoints
# Windows (PowerShell): $env:LSL_DATA_ROOT="$PWD\work\data"; $env:LSL_RUNS_ROOT="$PWD\work\runs"; $env:LSL_CKPT_ROOT="$PWD\checkpoints"
python -m pytest tests/ -q                                       # CPU suite; GPU tests skip
lsl-generate --config configs/data/multi_target_swarm_128.yaml --output_root $LSL_DATA_ROOT/smoke_128 \
    --total_scenes 40 --batch_size 20 --num_workers 2 --save_gifs false
lsl-train-gate --config configs/gate/A_stem2_bs1.yaml --data_root $LSL_DATA_ROOT/smoke_128 \
    --subset_size 40 --num_epochs 1                              # 1-epoch smoke run of the shipped recipe
```

Expected test result with no weights present: Tier 0 (CPU) 195 passed,
53 skipped (Tier 0 on GPU 221 / 27, Tier 1 242 / 6); the skips include the
four checks that need the weight files. No weight files ship:
`checkpoints/<name>.json` describes each one, and `safetensors_sha256` in it
is the identity of the original file. The step-by-step runbook, including
Tier 0 on GPU and Tier 1, full data generation, training, checkpoint loading
in a notebook and the pipeline evaluation, is `docs/runbook.md`.

## No weights in this package: day one

1. **Restore the names** ("Restoring the transferred tree", above); expect
   `PASS`.
2. **Install**: Tier 1 from source for training (Linux x86-64 or WSL2, NVIDIA
   GPU, CUDA 13.0 toolkit; `docs/environment.md`). Gate training needs the
   fused Mamba kernels on a 24 GB card; the reference Mamba of Tier 0 on GPU
   needs more than 40 GB to train the gate at 512². The classifier and
   segmenter train on any tier with a GPU.
3. **Run the tests**: `python -m pytest tests/ -q`; expect 195 passed /
   53 skipped on Tier 0 (CPU), 221 / 27 on Tier 0 on GPU, 242 / 6 on Tier 1.
4. **Generate the data** (`docs/data.md`, "Regenerating"):
   `multi_target_swarm_512x512x64` for the gate and the pipeline evaluation
   (3,000 scenes, about 94 GiB; about 6,865 s with 8 workers originally, inferred) and
   `swarm_128x128x64` for the classifier and segmenter (30,000 scenes, about
   59 GiB, six invocations; about 88 CPU-hours, 9,331 s on three machines
   with 20 workers each originally).
5. **Retrain** the three models (below), then **evaluate** them (runbook
   step 7, with your checkpoints) and compare with the targets.

| Model | Command (Tier 1) | Time | Target: `checkpoints/<name>.json` `val_metrics` |
|---|---|---|---|
| Gate | `lsl-train-gate --config configs/gate/A_stem2_bs1.yaml` | 50 epochs x about 1,478 s = about 20.5 h on a 24 GB GPU (**estimate**: one epoch measured on an RTX PRO 5000 laptop GPU, times 50); 8.05 GiB peak | `gate_A_stem2_bs1_ep42.json`: per-cell recall (k = 1) 0.9485, absent-cell flag rate 0.4024; with the classifier, per-target(group) recall 0.9486 (3930 / 4143) |
| Classifier | `lsl-train-classifier --config configs/classifier/baseline_30k.yaml` | 1,052 s per epoch **measured** on the original NVIDIA GB10 run (64 epochs to the selected checkpoint = about 18.7 h; the config plans 100 epochs, about 29 h, **estimate**); not timed on a 24 GB GPU | `classifier_baseline_30k_ep64.json`: val accuracy 0.9973; TP / TN / FP / FN 1494 / 1498 / 2 / 6 |
| Segmenter | `lsl-train-segmenter --config configs/segmenter/default.yaml` | 443 s per epoch **measured** on the original run (host not recorded), 150 epochs = 18.4 h | `segmenter_volseg_ep19.json`: val Dice 0.3909 / IoU 0.3183 at the selected epoch (val-loss selection, epoch 19); the same run reached Dice 0.8985 at epoch 150 |

Tolerances (`docs/results.md`, section 7): 0.005 on per-cell recall,
per-target recall and segmenter Dice / IoU; 0.0125 on the absent-cell flag
rate; 3 on each classifier count. Those tolerances were set for re-scoring
the *same* weights. A retrain is a new run (GPU non-determinism, data
regenerated), so read a result just outside them as "check", not
"regression", and keep these known behaviours in mind:

- **Gate:** the recipe is seed-bistable; one retrain can land in the cautious
  basin (per-cell miss rate about 28%). Train at least 3 seeds (`--seed`) and
  select on per-target recall with the classifier, not on the trainer's
  `cluster_recall`. The trainer writes `models/best_gate_model.pth` only from
  epoch 30 on, when the absent-scene criterion is met.
- **Classifier:** in the original run, validation accuracy stayed at chance
  (0.50-0.52) for the first 12 epochs, then rose (0.661 at epoch 13, 0.755 at
  epoch 15, 0.997 at epoch 64). A flat start is expected.
- **Segmenter:** the shipped recipe selects on validation loss, which picks an
  early, weak epoch (Dice 0.39); Dice passed 0.8 at epoch 49 and peaked at
  0.904 (epoch 125). To reproduce the manifest, keep the recipe; for a usable
  segmenter, select on Dice instead (`docs/limitations.md`, item 1).

Outputs land in `$LSL_RUNS_ROOT/<run_name>/models/` (`docs/runbook.md`,
step 9). Pass them to the evaluation scripts by path; to keep one, convert it
with `scripts/checkpoints/to_safetensors.py` and write a new manifest under a
new name.

## If the weights arrive separately

Put the three `<name>.safetensors` files in `checkpoints/` (or the directory
`LSL_CKPT_ROOT` names) under the names in the manifests and check them
against `safetensors_sha256` (`docs/runbook.md`, step 3). Everything else in
these docs then applies unchanged: the default checkpoint names of every
script resolve, and the test suite gives 199 passed / 49 skipped on Tier 0
(Tier 1: 246 / 2).
